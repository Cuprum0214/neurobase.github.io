# DECISIONS · 决策记录

> 回答一个问题：**为什么这样决定？**
> 记录重要决定 + 原因 + 当时的取舍。
> 目的：换一个对话、换一个 AI 时，决策背景不会"不见了"；答辩时能讲清"为什么不是另一个方案"。
> 编号从小到大按时间追加；被后续决策取代时，**不删除原文**，在被取代条目下补「更新 / 取代」说明。

---

## 三份迭代档案的分工

| 文件 | 回答什么问题 | 里面放什么 | 写入时机 |
| --- | --- | --- | --- |
| `DEV_LOG.md` | 每个阶段做了什么 | 完成事项、遇到的问题、下一步 | 每一轮更新后 |
| `DECISIONS.md`（本文件） | 为什么这样决定 | 重要决定 + 原因 + 当时的取舍 | 出现**选型 / 方案 / 取舍**时 |
| `ERROR_LOG.md` | 从错误里学到了什么 | 只记几个有学习价值的错误 | 出现**可复用的教训**时 |

## 记录格式

```
### D-编号 · 决定标题（日期）
- 决定：
- 背景：
- 备选方案：
- 选择理由：
- 取舍/代价：
- 是否可逆：
```

## 维护约定（硬性）

1. 只有当本轮出现**真正的选择**（技术选型、方案取舍、放弃某功能、改变约定）时才新增；纯实现细节不写。
2. 新条目追加在文件末尾 `<!-- 从这里继续往下追加 -->` 之上，编号顺序递增，**不得跳号或复用**。
3. 被推翻的旧决策保留原文，只在其下追加「更新（日期）」；新决策需写明「取代 D-xxx」。
4. 每轮更新后，在 `DEV_LOG.md` 对应条目和 `DEV_LOG.md` 的「阶段总览」表中引用本文件编号。
5. 若同一轮踩到有普遍价值的坑，同步写入 `ERROR_LOG.md` 并互链。

## 决策列表

### D-001 · 采用"全栈 + 300 词条 + AI 助教"方案（2026-10-10）
- 决定：技术形态定为 React/Vue + Supabase + Cloudflare Workers AI 助教 + Realtime。
- 背景：原工作区基线是"纯静态 15 章"，用户重新选定全栈方案。

### D-059 · 液体用「惯性驱动 + 二阶驻波 + 角动量翻滚」的解析近似，不引入流体求解器（2026-11-19）

- 背景：用户要求「拖动速度不同 → 液体晃动不同」「极快拖动可翻滚、水花明显」「在技术与运行能力允许前提下最大程度贴近现实物理」。
- 备选方案：① 真流体（SPH 或 PBF）跑在 Worker + OffscreenCanvas/WebGL，物理最真实；② 保留解析模型但补足关键定性行为（本方案）；③ 纯关键帧动画按速度分档。
- 选择理由：在 56–66px 的球里，SPH 的精度肉眼不可辨，但成本很高——需要自绘玻璃、采样背景文字、维护粒子纹理与 DPR，还会与 `backdrop-filter` 合成冲突。解析模型能复现用户真正能感知的定性差异：匀速几乎不晃、急加速大晃、急停反向过冲、能量越大回摆越久、角动量带来翻滚。三通道各自独立可调，参数集中在 4 组常量与 3 个增益里。

### D-060 · 水花用「溅射环 + 水柱 + 错落水珠」的解析组合，不引入粒子系统（2026-11-19）
- 决定：水花表现由三组 CSS 元素叠加而成——液面处的溅射环（`.nb-ai-fab-splash`，随 `slosh` 放大淡入）、两根从液面向上冲起的水柱（`.nb-ai-fab-spout`，高度随 `slosh` 拉长）、四粒高低错落的水珠（位移倍数 0.56 / 0.7 / 0.92 / 1.0）。全部由同一个 `--liquid-slosh` 与 `--splash-x/-y` 驱动，垂直与水平甩动共用。
- 背景：用户要求「快速上下拖动时看到水花翻滚特效」，之前水花只跟随水平速度，垂直甩动时几乎不出现。
- 备选方案：① 真实粒子系统（几十个元素或 Canvas 粒子，按抛体运动模拟）；② 少量元素 + 变量驱动的解析组合（本方案）；③ 直接播放一段 GIF / Lottie。
- 选择理由：球只有 56–66px，几十个粒子在这个尺寸下会糊成一团，且每帧要写大量变量或重绘 Canvas；解析组合只需要 3 类元素、2 个变量，视觉上已经能表达「溅起—散开—回落」。GIF 无法与拖动强度和液面高度同步，会显得假。
- 取舍/代价：水珠不是真抛体，只有上跳位移与透明度，没有重力回落曲线；水柱是直线而非抛物线；四粒水珠是固定位置，不随甩动方向随机分布。垂直方向靠 `ayS` 通道补足惯性，而不是给每粒水珠独立速度。
- 是否可逆：可。DOM 中 `.nb-ai-fab-splash / .nb-ai-fab-spout / .nb-ai-fab-drop` 与物理通道解耦，换成粒子只需替换这一层并保留 `slosh` 输入。

### D-061 · 垂直晃动采用「加速度驱动位移 + 轴对称曲率 + 脉冲水花」，禁止竖直方向的整体旋转（2026-11-19）
- 决定：
  1. 液面位移 `level` 由**竖直加速度** `ayS` 主导（`-ayS*24`），速度项只保留 0.8 的粘滞拖曳；
  2. 新增轴对称曲率 `bulge`（中心上鼓 / 下凹），由 `ayS` 驱动，与液面亮线、气泡层联动；
  3. 水花改为**脉冲** `burst`，只在加速度突变（|dvY| > 0.45，含掉头与松手急停）时注入，约 0.3s 衰减；
  4. 竖直方向不向 `spinV` 输入角动量；松手时只有水平分量 `|lastVx| > 0.2` 才触发翻滚与驻波；
  5. 手指停住超过 90ms 视为容器静止，惯性输入与准静态目标一起归零。
- 背景：上一版把水平通道「速度→倾角」直接复制到竖直方向，导致匀速拖动时液面持续偏移、水花常驻、上下甩动时水体整体旋转 —— 与真实液体运动不符。
- 备选方案：① 完全按连续流体方程（Navier–Stokes / SPH）求解；② 用「等效重力 g_eff = g − a」解析近似（本方案）；③ 继续用速度驱动的经验公式。
- 选择理由：56px 球体内看不到真实流动细节，但**因果关系**必须对：加速度→液面位移、加速度突变→水花、无水平加速度→不旋转。方案 ② 用 3 个通道（level / bulge / burst）就覆盖了这三条因果；方案 ① 成本远超收益；方案 ③ 已经证明方向错误。
- 取舍/代价：液面位移是准静态近似，没有真实的「液体整体滞后 + 中心先凹后凸」时序；曲率只有单变量（不能区分边缘爬升与中心凹陷的相位差）；水花不区分方向（掉头与急停走同一条脉冲）。这些在 56px 尺寸下不可辨。
- 是否可逆：可。`level / bulge / burst` 三个变量与 DOM 解耦，若将来换 WebGL 液体，只需把这三个值映射到顶点位移。

### D-062 · 流动感来自「低阻尼 + 内部漂移 + 持续气泡」，不靠提高不透明度或堆粒子（2026-11-19）
- 决定：
  1. 液面升降改为欠阻尼（`Z_L 0.30`），松手后允许回弹 2~3 次；倾角阻尼从 0.13 降到 0.115；
  2. 新增 `drift`：水体层以 3.4/s 追赶 `sway * 0.85`，永远慢外壳半拍；
  3. 新增 `ripple`：高频正弦叠加在液面线上，表达水面细波；
  4. 新增 3 个上浮气泡（7.2 / 9.4 / 11s），挂在液体层内部，由 `overflow: hidden` 裁在液面以下；
  5. 水体背景提高透明度、去掉 `conic-gradient` 硬边光纹，改用两层柔和径向光；
  6. 水珠透明度按 `burst²` 出现，避免小抖动时悬着白点。
- 背景：用户反馈「液体流动性再强一点，不要黏在球体里」。上一版为解决「甩过头」把 `Z_L` 调到 0.70（接近临界阻尼），代价是液体看起来像一整块凝胶在平移。
- 备选方案：① 继续加不透明度/饱和度，让液体更「亮」；② 加更多水珠与光斑；③ 降阻尼 + 增加内部流动细节（本方案）。
- 选择理由：黏滞感本质是**缺少相对运动**——外壳动、水也以同样节奏动，看起来就是固体。方案 ③ 制造了三种「水比容器慢」的相对运动（drift 滞后、气泡上浮、波纹抖动），同时保留水花只在冲击瞬间出现的规律。方案 ①② 只会让画面更花，不会更像水。
- 取舍/代价：欠阻尼让松手后多晃 1~2 次，`tilt` 回稳到 0.6° 以内的时间从 ~0.9s 延长到 ~1.3s；3 个气泡 + 3 个 CSS 动画在低端机上增加少量合成开销（非 rAF 驱动，走 compositor）。
- 是否可逆：可。所有新通道都是独立 CSS 变量（`--liquid-drift` / `--liquid-ripple`），气泡是独立元素，删除不影响物理。

### D-063 · 波幅与阻尼解耦：要更「浪」抬驱动增益，要收得住才动阻尼（2026-11-19）

  1. 液面幅度全部通过**驱动增益**扩大：`tiltTo` 9.6/5.2 → 12.0/6.2、`levelTo` 26/0.8 → 31/1.0、`waveTo` 0.075/0.014/0.34 → 0.115/0.020/0.46、`bulgeTo` 2.2 → 2.9、`ripple` 1.5 → 2.4px；

### D-072 · 用「液池垂直振子 + 守恒人工粘性」补上下甩动与锯齿，而不是改 2D 粒子（2026-11-19）

### D-073 · 液面「回平」的三件事：形状判静、端点延伸裁剪、二次阻尼（2026-11-19）
- 决定：
  1. `isCalm()` 增加 `tilt()` 形状判据（扣除整体水位后的液面最大偏离），而不是只调大 `calmT` 阈值；

  3. 用「二次阻尼 + 小振幅额外阻尼」组合压缩回平时间，而不是单纯加大线性 `drag`。

  - ④ 成本高，66px 下收益有限。
- 取舍/代价：最外 8 列是「拉平」而非真实物理（牺牲贴壁弯月面的细节）；二次阻尼让大振幅晃动更「稳」，极端甩动时液体显得比真实水更黏。

- **决策**：11 个模块各 29–32 条，总计 333 条；每条必须有至少 1 条真实教材来源；拼音/首字母由 `pypinyin` 生成后校验长度，不手写。
- **放弃的方案**：
  - 每模块精确 30 条：为凑齐数字会引入边缘或重复词条，降低质量。
  - 引用具体章节与页码：没有原文逐条核对时会制造不可验证的假来源，违反可追溯原则。
  - 手工输入拼音：223 条的量级下手误不可避免，且首字母长度必须精确等于汉字数。
- **影响**：后续扩容沿用同一规则（真实术语 + 真实教材 + 自动拼音校验）；`verify-native` 已改为动态断言，扩容不再需要改自测。
- **相关**：CHANGELOG v1.25.5、DEV_LOG 2026-11-20 条目、PROJECT_SCOPE v7.2。

### D-097 · 课程报告以「A4 打印版 HTML → 无头 Edge 导出 PDF」交付（2026-11-20）
- **决定**：① 报告写成单文件 HTML（内置 A4 `@page` 打印样式），用 Edge headless 的 `Page.printToPDF` 导出 `outputs/Wang Tong_NeuroBase.pdf`；② 交付物只保留 PDF 本体，源 HTML、截图与构建脚本放在 `.deepworks/tmp/report-work/`，不进入站点、不作为产物；③ 文件命名严格按课程规则 `Firstname Lastname_project name.pdf`（`Wang Tong_NeuroBase.pdf`）。
- **背景**：课程要求「report（pdf preferred）」，并规定了命名；报告需要嵌入截图、表格与分页控制。项目没有 Word / LaTeX 工具链，也不希望在仓库里新增构建依赖。
- **备选方案**：① 用 Word / Pages 手排后导出——无法复用仓库数据，改一处数字要手工改全文，且分页不可控；② 引入 Pandoc / LaTeX——排版质量高，但要装工具链、写模板，超出本任务范围；③ 用 `html2canvas + jsPDF` 在浏览器里拼——长文会被切成图片，文字不可选、体积大；④ **A4 打印版 HTML + 浏览器原生 printToPDF**。
- **选择理由**：④ 复用同一套 HTML/CSS 就能控制分页、页脚与图幅，导出的是**可选文本的矢量 PDF**；无需新增依赖（Edge 已在用于截图与探针）；数据统计可以直接从仓库读出后写入 HTML，减少手工抄写。
- **取舍/代价**：① HTML 与 PDF 两份形态，若数字变动需重跑脚本重新导出；② 中文排版依赖系统字体（雅黑），在别的机器上打开 PDF 不受影响，但重新导出可能字形略有差异；③ 源文件不入库，报告不可由仓库直接重建——故在 DEV_LOG 记录脚本路径与步骤，作为可复现说明。
- **是否可逆**：可。删除 PDF 不影响站点；后续若改用 LaTeX，只需停用 `make-pdf.mjs`。
- **传播**：`outputs/Wang Tong_NeuroBase.pdf`、`.deepworks/tmp/report-work/report.html`、`docs/CHANGELOG.md`（V5.0.0 交付物补充）、`docs/DEV_LOG.md`、`docs/PLAN.md`（v123）、`docs/PROJECT_SCOPE.md`（v7.1）。
