## 1. 项目目标

### 1.1 总目标
交付一个**可直接离线打开、内容准确、交互丰富、便于长期维护**的「神经与认知科学基础」学习网站，覆盖四大模块共 15 章，并配套实践（虚拟解剖 / 实验模拟 / 伦理辩论）与运营维护体系，适合大学本科入门水平。

### 1.2 分阶段目标
- 阶段 1：跑通「框架 + 样板章 + 全套基础设施」全流程，冻结设计系统与交互范式。
- 阶段 2-5：按模块横向复制，逐模块交付可用内容。
- 阶段 6：交付实践配套板块，完成全站打磨与总验收。

### 1.3 非目标（明确不做）
- 不做账号系统、后端、数据库、云同步。
- 不做付费/版权内容抓取，不嵌入第三方框架或 CDN。
- 不做原生 App / 小程序 / 服务端渲染版本。
- 不做医学诊断或临床指导内容（仅教学）。
- 不做 AI 写实插图（本期仅 SVG/CSS）。
- 虚拟解剖/实验模拟为**教学演示级**，不做科研级精度或真实数据采集上传。

## 3. 技术方案

### 3.1 技术约束（关键）
- **零构建**：不使用 npm / Vite / 打包器；所有文件手工维护。
- **离线优先 + 在线增强**：核心内容不得**自动加载**任何 CDN、外链字体、远程图片，断网双击仍完整可用；允许**用户主动触发**的在线核实外链（见 §3.5）。
- **file:// 兼容（硬约束）**：
  - 禁止 `fetch`/`XHR` 读取本地 JSON（`file://` 下被 CORS 拦截）。
  - 站点数据（章节元数据、术语表、题库、议题库）通过 `<script src="...">` 注入全局变量（如 `window.SITE_DATA`）。
  - 不使用 ES Module（`type="module"` 在 `file://` 下多数浏览器加载失败）；统一用经典 `<script>`。
- **进度与立场存储**：`localStorage`，键名前缀 `ncs.`，含版本号便于迁移。
- **浏览器目标**：最新版 Chrome / Edge / Firefox（桌面优先，兼顾移动视口）。

### 3.3 数据约定
- `window.SITE_DATA.chapters[]`：`{ id, no, title, titleEn, module, file, order, goals[], keyTerms[], hasViz[] }`
- `window.SITE_DATA.pages[]`：`{ id, title, file, group: "content|lab|help" }`（供站点地图与导航生成）
- `window.GLOSSARY[]`：`{ term, termEn, definition, chapterId, tags[] }`
- `window.ETHICS_ISSUES[]`：`{ id, title, background, pros[], cons[], frameworks[], questions[], stanceStored }`
- 题库内嵌于各章 HTML：`<script type="application/json" id="quiz-data">[...]</script>`
  - 每题：`{ id, type: "single|multi|judge", stem, options[], answer[], explanation }`

### 3.4 UI 主题与视觉风格要求（蓝色系科幻风格）

全站统一采用**蓝色系科幻（Sci-Fi Blue）**主题，营造"科研仪器 / 太空舱 HUD"式的沉浸观感；所有页面与可视化必须遵循同一套设计令牌（design tokens）。

#### 3.4.1 色板（基线，阶段 1 可微调但须记入变更记录）
| 角色 | 变量 | 值 | 用途 |
| --- | --- | --- | --- |
| 深空背景 | `--bg-deep` | `#060B18` | 页面最底层背景 |
| 主背景 | `--bg` | `#0A192F` | 内容区背景 |
| 面板/卡片 | `--surface` | `#112240` | 卡片、侧边栏、浮层 |
| 玻璃层 | `--surface-glass` | `rgba(17,34,64,.72)` | 玻璃拟态面板 |
| 主强调 | `--accent` | `#00E5FF` | 电光青：链接、图标、关键高亮、发光 |
| 次强调 | `--accent-2` | `#4D7CFE` | 科技蓝：按钮、选中态 |
| 点缀 | `--accent-3` | `#7C4DFF` | 霓虹紫：少量点缀，禁止大面积使用 |
| 主文本 | `--text` | `#E6F1FF` | 正文 |
| 次文本 | `--text-muted` | `#8892B0` | 辅助说明 |
| 边框 | `--border` | `rgba(0,229,255,.22)` | 分割线、卡片描边 |
| 成功 | `--ok` | `#00E676` | 测验正确、进度通过 |
| 警告 | `--warn` | `#FFB300` | 常见误区提示框 |
| 错误 | `--err` | `#FF5252` | 测验错误、死链提示 |
| 发光 | `--glow` | `0 0 12px rgba(0,229,255,.45)` | hover / 焦点发光 |

#### 3.4.2 字体
- 中文/正文：`"Microsoft YaHei", "PingFang SC", system-ui, -apple-system, sans-serif`
- 数据/代码/公式：`Consolas, "Cascadia Mono", "Courier New", monospace`
- 标题可加轻微字距（letter-spacing）与发光文字效果，强化科技感。
- **不得引用外部字体**（离线约束）。

#### 3.4.3 视觉元素
- **网格底纹**：CSS 渐变网格背景，低透明度，营造坐标/HUD 感。
- **发光边框**：卡片 hover 时边框转 `--accent` 并加 `--glow`。
- **玻璃拟态**：面板用 `backdrop-filter: blur()` + 半透明，须保证文字对比度。
- **HUD 装饰**：标题/图表角落可用细线、坐标刻度、切角（`clip-path`）装饰。
- **渐变强调**：标题、进度条用 `--accent-2` → `--accent` 蓝青渐变。
- **数据可视化**：线条/节点用 `--accent`，与背景网格呼应，统一线宽规范。

#### 3.4.4 动效
- 克制：hover 发光、渐变过渡、进度条填充、可视化播放；时长 150-300ms。
- 必须尊重 `prefers-reduced-motion`，提供关闭动效的降级方案。
- 不做干扰阅读的背景循环动画。

#### 3.4.5 深浅模式
- **默认深色科幻主题**（如上色板）。
- 提供亮色模式（浅蓝白底 + 深蓝文字，`--accent` 保持），供打印/强光环境；`print.css` 走无背景、高对比。
- 主题切换持久化于 `localStorage`（`ncs.theme`）。

#### 3.4.6 可访问性
- 正文对比度 ≥ WCAG AA（4.5:1）；发光装饰不得降低文字可读性。
- 不以颜色作为唯一信息载体（正确/错误同时给图标与文字）。
- 焦点态可见（`--glow`）。

### 3.5 在线核实能力（Online Verification）

> 定位调整：站点由「严格离线」升级为「**离线优先 + 在线增强**」。核心学习功能在断网时仍 100% 可用；联网时提供学术来源与版次核实能力。

#### 3.5.1 能力分级
| 模式 | 触发 | 行为 | 依赖 |
| --- | --- | --- | --- |
| 离线基础（默认） | 无网络 | 全部学习功能正常，来源以纯文本呈现 | 无 |
| 在线核实（用户触发） | 点击「核实来源」 | 新标签打开权威检索（DOI / 出版社 / Crossref / PubMed / WorldCat），供人工核对最新版次 | 网络 + 浏览器 |
| 在线自动核查（正式） | 站点以 `http(s)` 托管，或点击「检查来源更新」 | 联网查询来源库版次并提示更新（Crossref / OpenLibrary / Google Books） | 网络 + 支持 CORS 的公共 API |

#### 3.5.2 引用核实链接规范
- 每条关键来源在 `references-data.js`（`window.REFERENCES`）登记：
  `{ id, claim, sourceType, authors, title, edition, year, publisher, identifiers: { isbn, doi }, verifyUrls: { publisher, doi, scholar, worldcat } }`
- 界面每条来源提供 `[核实来源 ▸]`：跳转 DOI 解析、出版社官网、Crossref / PubMed、WorldCat / Google Books 检索。
- 核实链接**仅由用户主动点击**触发，不作为自动加载资源。
- 末尾「参考来源」区（§5.2.7）每条目附对应「核实来源 ▸」链接。

#### 3.5.3 技术约束调整（重要）
- **保留**：不使用第三方脚本 / 字体 / CDN 作为**自动加载**资源（保障离线与隐私）。
- **放开**：允许用户主动点击的**外部核实链接**与在线检索。
- **运行环境与自动核查**：`file://` 下无法可靠自动跨域查询；**自动核查在 `http(s)` 托管下正式启用**（目标 API 支持 CORS）。因此：
  - 「用户触发在线核实」在 `file://` 与 `http(s)` 下均可用（点击跳转不受 CORS 限制）。
  - 「自动核查最新版次」在 `http(s)` 托管时可用，使用支持 CORS 的公共学术 API（Crossref / OpenLibrary / Google Books）。
  - 不引入后端（维持 N1）；无网络或 `file://` 时自动降级为「用户触发」模式，不报错。
- `check_offline.mjs` 判据更新：**自动加载资源** 0 外部依赖；用户触发的外链不计为违规。
- 新增 `check_references.mjs`：引用与 `REFERENCES` 库一致、`verifyUrls` 格式合法、联网时抽检可达。

#### 3.5.4 版次核实
- 教材/著作登记**版次与年份**；联网时可核对是否有更新版次。
- 发现新版次时，经人工确认后更新来源库并记入 `changelog.html`。

#### 3.5.5 部署与运行方式
| 方式 | 打开方式 | 离线基础 | 用户触发核实 | 自动联网核查 |
| --- | --- | --- | --- | --- |
| 本地离线 | 双击 `index.html`（`file://`） | ✅ | ✅ | ✖（跨域受限，自动降级） |
| 静态托管 | `http(s)://`（GitHub Pages / Netlify / 本地 `http-server`） | ✅ | ✅ | ✅ |

- 站点零构建，可直接部署到任意静态托管；提供 `docs/DEPLOY.md` 说明两种运行方式。
- 自动核查仅在 `http(s)` 环境启用；检测到 `file://` 或无网络时静默降级为「用户触发」模式，不报错、不阻塞。

#### 3.5.6 来源自动核查（Crossref / OpenLibrary / Google Books）
- 数据源（均支持 CORS）：Crossref REST（DOI / 标题）、OpenLibrary（ISBN）、Google Books API（ISBN / 标题）。
- 流程：读取 `window.REFERENCES` → 按 DOI / ISBN 查询 → 比对 `edition` / `year` → 标注「可能有更新版次（在线）」，并附核实链接。
- 触发：来源面板「检查来源更新」按钮（用户主动），或站点加载时的可选提示（默认关闭，尊重离线）。
- 缓存：结果写入 `localStorage`（键 `ncs.refCheck`，带时间戳，TTL 7 天）。
- 降级：请求失败 / 超时 / 无网络 → 保留本地数据，提示「离线或不可用」，不阻塞页面。

## 5. 每章内容模板（强制结构）

每章 HTML 必须包含以下区块，顺序一致：

1. `<header>` 面包屑 + 章标题（中英）+ 所属模块
2. 「学习目标」列表（3-5 条，可勾选）
3. 正文小节 4-6 个（每个含 `<h2>`，必要处 `<h3>`、图示、例子框）
4. 「本节小结 / 要点回顾」（列表）
5. 「关键术语」（链接到 glossary.html 锚点）
6. 「自测」测验区（8-12 题）
7. 「延伸实践」（链接到相关 labs 页面，可选）
8. 「上下章导航」页脚

正文计量只统计中文正文（不含导航、代码、术语表），目标 1500-2500 字。

### 5.1 知识点粒度与深度规格

> 本节定义「一个知识点要写到多细」，是内容生产与 AI 内容自测的共同标尺。

#### 5.1.1 深度标尺（本科入门）
1. 讲清「是什么—为什么—怎么发生—有何意义」，**不做公式推导**。
2. 给关键数值与典型参数，**但不要求计算**（如静息电位 ≈ -70 mV）。
3. 术语首次出现给**中英对照 + 一句话定义**，并收入术语表。
4. 经典实验/证据只给**结论与意义**，不展开方法细节。
5. 争议/前沿内容明确标注「**了解**」，不喧宾夺主。
6. 抽象概念至少配 **1 个图示或类比**，纯文字不算讲透。

#### 5.1.2 四级粒度
```
模块 Module（4）
└─ 章 Chapter（15）
   └─ 小节 Section（每章 4-6 个）
      └─ 知识点 Key Point（每小节 2-4 个 → 每章 8-12 个）
         └─ 原子概念/术语 Concept（进术语表，可检索）
```

#### 5.1.3 知识点标准单元（七要素，强制）
| # | 要素 | 内容 | 对应功能 |
| --- | --- | --- | --- |
| ① | 定义 | 一句话是什么（中英对照） | 术语表 / 闪卡 |
| ② | 机制 | 因果链，怎么发生 | 正文 + 动画 |
| ③ | 关键结构 | 由什么构成、在哪里 | 标注图 |
| ④ | 关键数据 | 数值、单位、典型范围 | 正文强调框 |
| ⑤ | 图示 | 至少 1 个可视元素 | 5 类交互可视化 |
| ⑥ | 常见误区 | 易混淆 / 易错点 | 测验干扰项 |
| ⑦ | 关联 | 前置 / 后续 / 跨模块 / 应用 | 交叉链接 |

> 可选补充：生活化例子、经典证据来源。

#### 5.1.4 公式规则
- 呈现关键公式（如 Nernst 方程、GHK 方程）**但不推导**，每个公式配一句「怎么读 / 说明什么」。
- 不出现需要求导/积分的推导；测验不设计算题。
- 数值以定性对比与典型量级为主。

#### 5.1.5 误区与前沿规则
- 每个知识点至少 1 条「常见误区」，并作为测验干扰项的来源。
- 争议或前沿内容用统一标注样式（如「了解」徽标），与主干内容视觉区分。
- 前沿内容点到为止，以教材与代表性工作为准，不追最新文献。

#### 5.1.6 量级基线
| 指标 | 估算 |
| --- | --- |
| 知识点 | 120-180 个（15 章 × 8-12） |
| 正文字数 | 2.3-3.8 万字 |
| 测验题 | 120-180 题 |
| 术语 | 150-250 条 |

### 5.2 内容准确性与引用规范

> 目标：全站知识陈述与引用**可溯源、准确、合规**。AI 生成内容不单独保证 100% 无误，采用「来源基准 + 结构化标注 + 自动校验 + 人工/专家复核 + 勘误」五重机制兜底。

#### 5.2.1 来源基准（权威优先）
- 以主流教材与领域共识为准，优先（但不限于）：
  - 《Principles of Neural Science》(Kandel et al.)
  - 《Neuroscience: Exploring the Brain》(Bear et al.)
  - 《Neuroscience》(Purves et al.)
  - 《Fundamental Neuroscience》(Squire et al.)
  - 《Cognitive Neuroscience: The Biology of the Mind》(Gazzaniga et al.)
  - 全国科学技术名词审定委员会《神经科学名词》等规范译名
- 知悉度分级：**教材共识 > 综述 > 单篇研究**；结论冲突时以共识为准，并标注分歧。

#### 5.2.2 术语与译名
- 术语首现给**中英对照**；中文译名优先采用规范/通用译法，存在争议的译名并列标注。
- 全站术语唯一化，统一收入 `glossary-data.js`（`term`、`termEn`、`definition`、`chapterId`、`tags`）。

#### 5.2.3 数据与事实
- 关键数值给**典型范围与单位**，并注明条件（如「静息电位约 -70 mV」）。
- 不做无来源的伪精确；不确定或存在争议处显式标注。
- 计量单位采用 SI 常见写法。

#### 5.2.4 引用规范
- 需注明来源的关键结论，以**可溯源字段**记录：`{ claim, sourceType, source, locator }`（结论 / 来源类型 / 来源 / 定位如章节或页码）。
- 引用必须**真实存在**：禁止编造作者、书名、年份、页码、DOI；不得「幻觉」引用。
- 呈现方式：正文可就近给出**纯文本**来源（如 `Kandel et al., 5th ed., Ch. 9`）；并**必须**在正文末尾设「参考来源」区（详见 §5.2.7）。
- **离线约束**：不使用可点击外链，来源以纯文本呈现；`check_offline.mjs` 仅扫描**资源加载型**外部依赖（`src`/`href`/`@import`/`url()`/`<link>`、CDN、外链字体），**不**将正文文本中的来源名或文献字样判为外部依赖。
- 不得复制受版权保护的原文段落，以自撰表述转述。

#### 5.2.5 禁止项
- 禁止编造引用、数据、实验结论。
- 禁止把争议观点当作定论；禁止把教学演示表述为临床结论。
- 禁止成段复制教材原文。

#### 5.2.6 复核与勘误
- 每章交付前经**人工/领域复核**；错误修正须记录到 `changelog.html` 并重跑自测。
- 最终页面通过版权页免责声明说明「教学用途、可能存在简化」。

#### 5.2.7 内容末尾引用标注（强制）
- **凡学习内容涉及引用，必须在该页正文末尾设「参考来源」区**，集中列出本页所有引用；已给引用而末尾缺失视为未完成（Chapter DoD 不通过）。
- 位置：正文学习内容末尾（小结与关键术语之后、测验之前）；全页引用统一汇总于此。
- 正文内标注：用上标编号（如 `[1]`）或 `（作者, 年份）`，与末尾条目**一一对应**。
- 每条目字段：序号、作者、题名、版次、年份、出版社/期刊、标识符（ISBN/DOI）、可选「核实来源 ▸」链接（§3.5.2）。
- 每条目须在 `window.REFERENCES` 中有对应登记，供 `check_references.mjs` / `check_citation.mjs` 校验。
- 若本页不涉及引用，应在该位置显式标注「本页为教材共识综述，未直接引用」，不得留空。
- 同样适用于实践配套页（虚拟解剖 / 模拟 / 辩论）：凡引用必标。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| `file://` 下 fetch/module 失效 | 数据加载失败 | 全程用经典 script + 内联 JSON，已写入技术约束 |
| `file://` 下 localStorage 行为差异 | 进度/立场丢失 | 键名带版本；失败时降级为会话内存并提示 |
| 中文字体缺失导致排版差 | 视觉不一致 | 只用系统字体栈，不依赖外部字体 |
| 内容科学性错误 | 学习误导 | 关键结论标注来源类型；人工逐章验收把关 |
| 内容/引用不准确或编造 | 误导、失信 | §5.2 来源基准 + 可溯源字段 + `check_citation.mjs` + 人工/专家复核 + 勘误记录 |
| 可视化/实验代码量大拖慢进度 | 阶段延期 | 阶段 1 冻结组件范式与 SVG 规范，后续复用 |
| 虚拟解剖 SVG 复杂度高 | 质量参差 | 建立分层 SVG 组件库与统一配色/线宽规范 |
| 伦理议题立场敏感 | 引发争议 | 中立呈现正反方，不下结论；提供伦理框架而非价值判断 |
| 实践配套范围膨胀 | 无法退出 | 阶段 6 内锁定量（1+3+3+1），增删记入变更记录 |
| 范围蔓延 | 无法退出 | 变更须写入「变更记录」并重新验收 |
| 联网核实不可用 / CORS 限制 | 自动核查失效 | 以「用户触发纯链接核实」为主；自动核查仅作可选，依赖 CORS 公共 API 与 http(s) 托管 |
| 外部核实链接腐烂（link rot） | 核实失效 | `check_references.mjs` 联网抽检 + 每来源提供多入口（DOI/出版社/WorldCat） |
| 自动核查依赖第三方 API 稳定性 | 核查偶发失败 | 多源（Crossref/OpenLibrary/Google Books）+ 缓存 TTL + 失败静默降级 |
| Supabase 免费项目长期无活动被暂停 | 在线反馈失效 | 自动降级到离线模式，不阻塞学习；`docs/supabase/README.md` 说明唤醒方式 |
| Supabase 在国内网络可达性不稳 | 在线反馈不可用 | supabase-js 本地化（`vendor/supabase.js`，不走 CDN）；不可达时静默回退离线；问卷仍可用复制/邮件出口 |
| 误将 `service_role` key 写入前端 | 数据被绕过 RLS 读写 | 前端只用 `anon` key；RLS 不为 anon 开表级策略，写入仅经 `SECURITY DEFINER` RPC；文档显式警告 |
